# Architecture

The hub discovers manifests. The Design SDK owns IndexedDB, the design and project models, the shell, and the portable ZIP format. Each route supplies an adapter for its complete inputs. Saved reports reopen as editable Canvas worksheets. Saving from the report view updates its snapshot while retaining the originating calculation inputs and the hash of the generated snapshot. The package viewer reuses the Canvas print geometry to assemble saved reports in project order.

Two pinned Git submodules retain upstream history. The build stages their native entry points and integration changes in a disposable directory. The small asset and UI packages supply the steel catalogue reader and drawing components shared by Steel and Composite. The build copies the upstream catalogue and notices with the IDs intact. Extraction of the full engine, report, and visualization packages remains a separate migration. The boundary checker covers platform source. Existing Canvas imports remain inside the pinned dependency.

mConcreteRecCol uses the copied MBColumn Lite numerical core inside a browser worker. The registry keeps the `mbcolumn-lite` ID and route so existing design packages and drafts reopen. The platform saves column and optional shear inputs. The worksheet adapter copies calculated results and interaction diagrams into a Canvas document. Native HTML and PDF exports include the directional shear results when enabled.

The shear check follows the [RC Rectangular Column Check worksheet](https://github.com/Anhbq1298/mCalcCanvas/blob/161910b4d162361e53217b6251a29d779cd30a91/templates/RC_Rectangular_Column_Check.mCCV) and EN 1992-1-1:2023 §8.2.3. It checks concrete strut and supplied links separately for each direction. The app checks both faces for unsymmetrical reinforcement and reports the higher utilization. Automatic layout generates rectangular hoops and cross-ties from perimeter reinforcement and shares their directional leg counts with the shear check. Uniform bundled bars use the bundle envelope for the geometry and one restraint location per bundle. Manual entry remains available for custom detailing and existing saved designs. The PMM and slenderness checks retain their existing material model and code edition.

mConcreteCircCol keeps the `rc-circular-column` route and `.mccol` format. Its geometry and section solvers are tool-owned. A browser worker checks a single action set and produces a Canvas report snapshot. See the [circular column design basis](CIRCULAR_COLUMN.md) for the geometry, code scope and regression case.

mPunchingShear checks internal, edge and corner slab–column connections to EN 1992-1-1:2004 §6.4 and §9.4.3, with the CEN recommended values or a UK NA profile that must be confirmed. Perimeters and link layers are clipped to the slab and to openings and their §6.4.2(3) shadows on the exact path geometry. The solver, perimeter geometry and link layout are plain modules inside the tool. Every physical link is an object with its own legs, and a leg counts only when it lies inside the slab and outside openings. Auto design produces one layout that envelopes all combinations; check-provided mode never moves the user's links. Drop panels and column heads (§6.4.2(8)–(11)) are solved by `head.mjs` as separate control sections through the same solver and merged so that the worst section governs. Input labels are written in LaTeX and rendered to MathML by `tex.mjs` without a runtime dependency. Twelve worked cases live in `examples.mjs`. Unsupported geometry, unsupported loading, unconfirmed profile values and unconfirmed link engagement keep the design from reporting Pass. The plan and the two sections (A–A along local x, B–B along local y) are SVG strings that the page and the report both use. The report is generated as a Canvas worksheet with live formulas, and `npm run test:punching-canvas` evaluates it with the Canvas engine against the solver. Sources and benchmark records are in `tools/punching-shear/SOURCES.md`.

mConcBreakout checks a cast-in steel plate with welded reinforcing bars and headed studs under N, V and M in one plane. By default a flexible-plate FE model (`fem/`: MITC4 plate elements on compression-only concrete springs and tension-only bar and stud springs, with the steel member as a rigid footprint, solved by a banded Cholesky with the master DOFs bordered) distributes N and M. The rigid-plate equilibrium (`equilibrium.mjs`) remains as an option and as the comparison: it finds the tension–compression couple from bearing comes from the EN 1993-1-8 §6.2.5 flange T-stub, or optionally a full-width block, and tension is shared by a linear strain field. The welded bars are checked for steel, the bar-to-plate weld, plate shear and EN 1992-1-1 anchorage. The plate is checked as a yield-line strip from the member weld toe. The studs are checked to EN 1992-4 §7.2: steel, pry-out, edge breakout and, when studs share tension, cone, pull-out, splitting, blow-out and interaction. Blow-out, uncovered plate bending and an unconfirmed transfer into the member reinforcement keep the design from reporting Pass. The plan, the section and the 3D view (`view3d.mjs`, an orthographic SVG projection with depth sorting, so it needs no WebGL dependency) are SVG strings shared by the page and the Canvas report. Sources and benchmarks are in `tools/conc-breakout/SOURCES.md`.

GitHub Pages must use GitHub Actions as the source. The workflow deploys on `main` after validation. Existing production URLs can be switched after the new site and data migration are verified. Browser storage is tied to the HTTPS origin. For a cross-origin move, export from the old site and import the file on the new site.
